## Запуск

Із цієї папки можна використати вже встановлене середовище батьківського проєкту:

```bash
source ../venv/bin/activate
python main.py
```

На іншому комп'ютері спочатку створіть власне середовище:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python main.py
```

`main.py` виконує всі шість завдань. Для оновлення вебсторінок і погоди потрібен інтернет.
Дані Kaggle завантажуються через kagglehub, а наступні запуски використовують копії в `imputation_results/raw/`.
Ключ OpenWeather не потрібний і не використовується.

## Завдання і файли

| Файл | Завдання | Результат |
|---|---|---|
| A1.py | `parse_web_page(url)` | Текст без HTML-тегів; HTTPError при невдалому статусі |

Можна виконувати кожне завдання окремо: `python A1.py`, ..., `python A6.py`.

`python A4.py` вибирає дані з погодного JSON і записує CSV.
`python A5.py` будує графіки з наявного CSV.

## Спільний процес погоди

1. A2 робить HTTP-запит і записує JSON-відповідь у `result.json`.
2. A3 `prepare_weather()` викликає A2 для двох періодів і збирає потрібні поля у `weather.json`.
3. A3 читає з цього файла 19 серпня 2024 року (`2024-8-19`).
4. A4 вибирає іншу дату, 22 травня 1997 року (`1997-5-22`), записує її в `weather.csv` та читає CSV.
5. A5 візуалізує вибрану CSV-дату.

У `weather.json` — 96 погодинних записів: 18–20 серпня 2024 року та 22 травня 1997 року.
У `weather.csv` — лише 24 погодинні записи за 22 травня 1997 року.
`result.json` містить повну відповідь останнього API-запиту; кожен виклик `parse_api` перезаписує цей файл.
Числа в CSV при читанні стандартним csv.DictReader є рядками; A5 перетворює їх на float.

Джерело: [Open-Meteo Historical Weather API](https://open-meteo.com/en/docs/historical-weather-api).
Місто — Чернівці, координати 48.2921, 25.9358; час — Europe/Kyiv.
Історичні дані є реаналізом на основі вимірювань і моделей.
Одиниці: °C, відсотки вологості, мм опадів за годину та км/год вітру.

## A6

[Пояснення методів і результатів](A6_README.md).
Реальні пропуски у Students — 25 категоріальних значень lunch, заповнених модою.
У Wine Quality — 38 числових пропусків; для них застосовано KNN.
Mean, median, mode і KNN порівнюються за трьома однаковими наборами штучно прихованих відомих значень.
Це перевірка відновлення відомих значень, а не вимірювання невідомої помилки на реальних пропусках.
Обране масштабування: MinMax для оцінок і Robust для вина; порівняння всіх трьох способів збережено на графіках, а обрані дані — у normalized.csv.
Категорії й цільова оцінка quality не масштабуються.
`visualize_data(df)` у A6 працює також із послідовністю викликів із методички без ручного встановлення df.attrs.
